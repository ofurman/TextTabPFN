Can a task story help TabPFN-2.5 predict from few labels?

Text-conditioned thinking rows: two iterations of controlled experiments on synthetic causal scenes

Experiments run 2026-11-10 → 2026-11-12 on a local Apple M4 Pro (PyTorch MPS) · tabpfn 9.2.0, TabPFN-2.5 classifier checkpoint (frozen) · branch thinking-rows

Bottom line
  • Feeding the whole story as one pooled embedding into TabPFN-2.5's thinking rows did not help — neither with MiniLM nor with the stronger bge-base encoder. Pooled stories look almost identical to the encoder (cosine ≈ 0.99 between different stories).
  • Giving each feature its own role token through the same channel did help: 0.004–0.010 nats lower log loss than a matched control at n = 8–32 on held-out scene families, and corrupting the roles hurts.
  • Simple story-guided preprocessing (drop irrelevant features, merge redundant measurements) still beats every learned adapter at n ≤ 32 — but hurts at large n.
  • Each adapter was trained once, so training-run variance is not in the confidence intervals; the 4000-step role-token result is confirmed within a single adapter.

1. The question

A tabular foundation model like TabPFN-2.5 learns from a small labeled table in context. Often the table comes with a natural-language description of the setting. The research question: does giving the model that description — one shared story per dataset — improve predictions from few labels, and how does the benefit change as labels grow?

Both the story-aware model and its baseline receive the same labeled rows, the same feature schema and target definition; the only difference is access to the story. Improvement is a hypothesis under test, not an assumption.

2. Setup

Synthetic scenes with known ground truth

Each scene is a random causal graph (structural causal model) with 6–15 continuous features and a binary target. Every feature has one hidden role:

  • Markov blanket — directly influences y, or is directly influenced by y;
  • irrelevant — generated independently of y;
  • noisy measurement — one of 2–3 noisy readings of the same hidden cause of y.

Six mechanism families (linear, tanh, interaction × Gaussian or heavy-tailed noise). Families 0–3 train the adapters; families 4–5 (interaction mechanism) are held out and used for every reported verdict. Features are named neutrally (x1 … xp), so names carry no hint.

The story

Template text stating only structural facts — which features influence y, which are unrelated, which measure the same hidden quantity. No coefficients, signs, equations or noise levels. Example:

Known structure: x2, x4 and x6 directly influence y. x3 is directly influenced by y. x5, x7 and x8 are noisy measurements of one hidden quantity that influences y. x1 is unrelated to y.

Where the text enters the model

TabPFN-2.5 prepends 64 learned “thinking rows” that every column and every query row reads. The idea under test: shift those rows by a learned function of the story, θᵢ ← θᵢ + Wᵢ·e(t). TabPFN and the text encoder stay frozen; only Wᵢ (zero-initialized, so the model starts exactly at native TabPFN) is trained across thousands of synthetic scenes.

Fair comparison and statistics

  • Matched control: the same architecture, budget, episodes and learning rate, but reading only the schema (or neutral tokens). Story − control isolates the value of story content from generic retuning of the thinking rows.
  • Evaluation: 200 held-out scenes; support sizes n = 8 … 1024; 5 nested support draws per scene; 512 fixed query rows; every arm scores identical rows.
  • Metric: paired per-scene query log loss difference with a 95% scene-bootstrap CI (1000 resamples).
  • Verdict rule (fixed before any result, “D-08”): supported if the CI upper bound is below 0 at ≥ 2 of n = 8, 16, 32; harmful if the lower bound is above 0 at any of them; otherwise not supported.

The channel is large: a perfect text-to-rows mapping could cut log loss by 0.16 nats at n = 8. Per-column rows add only ~25–35% more, so the shared design was kept.

Training and held-out result (stages 2–5)

Frozen all-MiniLM-L6-v2 embedded schema + story; adapters trained for 32,000 episodes each. Both adapters beat native TabPFN by up to 0.012 nats at n = 16 — but the schema-only adapter got the same gain. On held-out families story − schema was −0.0008 / +0.0001 / +0.0012 at n = 8 / 16 / 32, verdict “harmful” by about 0.001 nats.

Corrupting the story told the same tale: removing it cost +0.0015 at n = 8, but swapping in another scene's story or permuting roles changed nothing measurable. The adapter noticed whether a story was present, not what it said. A diagnostic explained why: MiniLM embeddings of different stories had cosine similarity 0.989 among scenes with the same number of features — the role information was a tiny residual of the pooled vector.

Per-feature role tokens (stages 8, 9, 13)

Each feature xj gets its own token in slot j: the MiniLM embedding of one sentence stating only its role — “This feature directly influences y.”, “This feature is unrelated to y.”, “This feature is a noisy measurement of hidden quantity A, which influences y.” The sentence never names the feature; the slot position carries identity. A shared projection reduces the 15 slots into the same θᵢ + Wᵢ·s shift. The control puts the neutral sentence “This is a numeric feature.” in every slot.

Follow-on: a stronger pooled encoder (stages 10–11)

Because role tokens were “supported”, the pre-registered rule picked the stronger-encoder test: iteration 1's pooled design with frozen bge-base-en-v1.5 (768-d, 5.0M trainable parameters). Dev losses tied exactly (0.4377 vs 0.4377). Held-out: +0.0008 [+0.0000, +0.0017] at n = 8 — the rule prints “harmful”, but the call holds in only 69 of 100 bootstrap seeds (paired t-test p = 0.051). Effectively a null. bge's pooled stories are even more alike than MiniLM's (same-feature-count cosine 0.9936 vs 0.9886).

7. What this shows — and what it doesn't

Shows
  • A frozen TabPFN-2.5 can use story-provided structure through its thinking rows when that structure is exposed per feature.
  • Pooling the whole story into one sentence embedding loses the information — with a small or a stronger encoder.
  • The benefit is largest at few labels and fades as labels accumulate.
  • Wrong or irrelevant structure hurts the role-token adapter.
Does not show
  • Understanding of free-form text: roles were parsed exactly from templates.
  • Robustness to training seeds: each arm was trained once; the bootstrap covers scenes, not training runs. Only the 4000-step role result is confirmed within one adapter.
  • Results inside TabPFN's ensembled sklearn wrapper, on real datasets, or label savings (H2).
  • Corruption robustness for the 10k and bge arms.

Suggested next steps

  1. Train each arm with 2–3 seeds so verdicts include run-to-run variance.
  2. Extract per-feature roles from free-form or paraphrased stories with a local LLM and feed them as role tokens.
  3. Per-column thinking rows that bind each column's role token directly.
